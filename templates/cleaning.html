Applied Data Cleaning Rules

Strict Audit Policy: Records are not blindly deleted. Data cleaning rules eliminate only physically or logically impossible meter glitch records before performing EDA:

  • passenger_count > 0 — Eliminates unrecorded passenger values
  • trip_distance > 0 — Filters non-moving or canceled trips
  • fare_amount >= 0 & total_amount >= 0 — Drops negative meter glitch values
  • tpep_dropoff_datetime >= tpep_pickup_datetime — Resolves reverse timestamp corruption
  • 0.1 <= trip_duration_minutes <= 1440 — Keeps trips between 6 seconds and 24 hours
